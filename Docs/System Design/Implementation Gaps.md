# Implementation gap register

This register compares the implemented design documents with the current code and authored content as of 2026-11-16. It deliberately verifies code rather than repeating older “current state” paragraphs that some design documents have not updated. It records missing implementation and content, not every optional polish idea.

Use [Content and balance catalog](Content%20and%20Balance%20Catalog.md) for authoring locations and [System coherence](System%20Coherence.md) for the integration plan.

**Status after the save-service commit:** commits 1–10 of the [First steps implementation plan](First%20Steps%20Implementation%20Plan.md) are implemented and the full suite passes 63/63: the Trail/encounter slice, multi-target acts, the effect/stat seams and one versioned disk save service with Overworld checkpoints, a production Continue route and a second-process application-restart proof. Re-run the affected manual vertical-slice paths before recording those checks as newly passed (step 5 and the controller/audio passes still need a run). The next sequence is now concrete in [§12](First%20Steps%20Implementation%20Plan.md#12-phase-3--combat-breadth): commit 11 activates canonical class/equipment Move grants with persisted loadouts, commit 12 makes every generated/paid affix honest, and commit 13 differentiates AI and records repeatable encounter metrics. A save-management UI, user settings, secret-reward claims, dynamic spawns, Flair and Poker integration remain later work.

## Priority meanings

- **P0 — playable-loop blocker:** a system cannot complete its intended real-game flow, or disconnected ownership can duplicate/lose progress.
- **P1 — required mechanic/coherence:** a documented first-iteration rule or shared contract is absent or contradictory.
- **P2 — content and coverage:** the machinery exists but production content, authored variety, validation, or acceptance is missing.
- **Deferred:** explicitly outside the current iteration; listed so it is not mistaken for a completed feature.

## 5. Decided rules and remaining decision

The following decisions are canonical. The implementation work is to replace legacy behavior and encode these rules in tests, not to reopen them:

1. **HP and knockouts:** ✅ implemented in commit 4 — fighters start each Shootout at effective max HP, no persistent knockout debuffs, attrition is injected and On-Trail only; Vamoose routing remains commit 5.
2. **Bleed stacking and healing:** ✅ implemented in commit 4 — combined stack counts, two stacks per damage before resistance, healing removes stacks through the cleanse path.
3. **Vamoose loss:** remove half of money and a balance-selected 10–20% of remaining carried inventory. Equipped items and Bank contents are excluded. Exact item selection/rounding inside that range is balance data and must be deterministic and atomic. (Commit 5.)
4. **Basic attacks:** ✅ implemented in commit 4 — enemy AI gathers Moves only, the rat owns `Scratch`, and content validation requires an offensive Move for every combat actor.
5. **Boss HP conditions:** ✅ implemented in commit 4 — `hp_below` targets a named base actor with `fraction`/`amount`, optional `stat`/`winner`; boss content is still missing.
6. **Zone item acquisition:** ✅ implemented in commit 4 — the encounter Zone reaches `generateLoot()` and is validated canonically; Off-Trail loot stays empty.

### Remaining decision

7. **Poker rules:** “Texas hold'em” does not by itself communicate four-card flushes or every-player blinds. Record exact house rules before economy balancing.

## 7. Explicitly deferred, not blockers

The following should not be used to inflate the required first-iteration worklist: vendor schedules/haggling/buyback/per-town Banks, general fog of war/fast travel, moving visual parties, mid-fight reinforcements, direct unequip/drag-and-drop, player-selected loot, exact level-scaled Rodeo text in Character, cross-tab shortcuts, WFC reflection/backtracking/debug visualisation, and loading-screen progress art. They require new design only after the coherent core loop works.
